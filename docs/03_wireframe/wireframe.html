주석 — 화면2

  1. 1
    요청 정보 헤더 — 진입 시 GET /work-requests/{id} 200 WorkRequestDetail (latest_run, approvals 포함). 상태 칩은 status.
  2. 2
    데모 재생 / 에이전트 실행 — POST /work-requests/{id}/agent-runs 202 {run_id, overall_status:"RUNNING"} (409: 이미 APPROVED/DONE). 상태 REQUESTED→RUNNING.
  3. 3
    오케스트레이터 바 — 실행 후 2초 간격 폴링 GET /agent-runs/{runId}. Mock은 호출마다 step 1개씩 DONE(SPEC→LEGAL→SAFETY_DOC→VENDOR).
  4. 4
    에이전트 카드 ×4 — steps[].status(PENDING=대기 / RUNNING=실행 중 / DONE=완료)와 result 요약. 클릭 시 상세(호환표·조문·서류). 부품 상세는 GET /parts/{partId}/compatibility, 법령 추가 검색은 GET /laws/search?q=&equipmentType=&substance=.
  5. 5
    통합 요약 — 4개 DONE → overall_status=REVIEW, 요청 상태 REVIEW. summary 문장 표시. 엔지니어는 누락 보완 후 PATCH /work-requests/{id}/submit-approval 200 (422 누락 / 409 run 미완료) → PENDING_APPROVAL.
  6. 6
    승인 패널 — REVIEW 전에는 잠금. 엔지니어 역할은 읽기 전용, 안전관리자만 조작. 법령 3건은 A2 applicable_laws[], 조문 클릭 → 원문.
  7. 7
    체크리스트 4항목 — WORK_PERMIT · RISK_ASSESSMENT · LOTO_GAS_ISOLATION · GAS_DETECTOR_CHECK 모두 true여야 승인 버튼 활성(서버도 미완료 APPROVE는 409). 서류 링크는 GET /documents/{docId}.
  8. 8
    승인/반려/보완요청 + 코멘트 — POST /work-requests/{id}/approvals 201 Approval. body: decision, checklist{4}, comment. 성공 시 상태 APPROVED / REJECTED, 대시보드 평균 승인시간 갱신.
  9. 9
    역할 전환 토글 — 데모용(실서비스는 로그인 role). ENGINEER: 타임라인·승인 요청 활성, 패널 읽기 전용. SAFETY_MANAGER: 승인 패널 활성.
